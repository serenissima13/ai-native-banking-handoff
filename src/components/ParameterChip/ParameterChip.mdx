# ParameterChip

A parameter the assistant took from the person's request, shown where it was understood and changeable in place.

This page is the **working proof**: every example below is the real component, and every story runs as a test.

## Three separate questions

| | Question | Prop | Values |
|---|---|---|---|
| **Type** | How is the value changed? | `type` | `input` (pencil · Editing) · `select` (chevron · Open) |
| **State** | Where did it come from? | `state` | `confirmed` · `assumed` · `missing` · `edited` · `output` (read-only) |
| **Interaction** | What is happening now? | `open` · `editing` | `open` on a select · `editing` on an input · pressed and focused are browser states |

Try it in the controls: change `state` and the trailing icon stays; change `type` and it follows.

## What the tests check

Each story below runs in a real browser on every push, before anything is published:

- **Type drives behaviour** — a select announces its menu (`aria-haspopup`, `aria-expanded`) in every state; an input never does; `editing` is ignored on a select.
- **Interaction** — Editing: the field takes focus, ✕ clears, ✓ confirms with the typed value. Open: `aria-expanded="true"`.
- **Names** — each name contains the visible text word for word (WCAG 2.5.3).
- **Styles loaded** — `CssCheck` reads the computed 44 px min-height and the dashed Assumed edge from the token CSS.

The **Accessibility** panel runs axe on every story; switch **Theme** in the toolbar to check Light and Dark.
